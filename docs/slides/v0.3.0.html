The right model for each role

Each role gets its own model, effort level and tools, based on Anthropic's guidance and what other teams do.

Proposal as of 20 Oct 2026. The final design is in the spec (§1 and §3); some details here changed after the spike.
Use the arrow keys to move between slides · Print to save as PDF · Research: docs/research/agent-models.md

Problem

Today every role is a copy of your session

Today

  • The lead only says "dispatch each role as a subagent"
  • Every role runs on your session's model. On Fable that's $10 / $50 per million tokens, even for release notes
  • Every role gets every tool. The reviewer could edit code and the marketer could run shell commands; only the written rules stop them

After v0.3.0

  • Each role is a Claude Code agent with its own model and effort
  • Tools match the job: the reviewer can't edit and the marketer can't run commands
  • The lead escalates a role to a stronger model when it gets stuck
  • The skills don't change, so other AI tools work as before

Research 1 · Anthropic's docs

Change effort first, and keep strong models where judgement matters

Model$ / M tokens in · outDocs say it is for
Fable 5.110 · 50Demanding reasoning, long-horizon agentic work
Opus 5.54 · 20Long-running agentic coding and knowledge work
Sonnet 5.52 · 10Best mix of speed and intelligence; "most coding tasks"
Haiku 5.50.10 · 0.50High-volume, simple work; simple subagent tasks

Effort

low → max. Low suits simple subagents; high suits hard coding and reasoning. Lower effort often beats a cheaper model, so change effort before you change the model.

What this means for us

Cheap workers save money only on bulk, independent work. Ours is a chain (developer → tester → reviewer → QA). We split roles for independent review and a clean context, so the saving comes from right-sizing each role.

Research 2 · Other teams

Most teams agree on the same pattern

Who does what

  • Opus for review and security: Anthropic's code-review plugin, wshobson (202 agents), Claude Code's own example
  • Sonnet for code, tests and QA: Claude Code costs docs, feature-dev, VoltAgent
  • Haiku only for bounded, checkable work: search, file lists, simple drafts

Lessons learned

  • Reviewers are read-only (Read, Grep, Glob, Bash)
  • Always set the model. Leaving it out silently uses the most expensive one
  • The cheapest models take 2–3× the turns on multi-step work
  • Move up a tier when an agent gets stuck
  • Keep the team small; each agent multiplies tokens

Gap: no published benchmark compares a cheap reviewer with an Opus reviewer. So the reviewer stays strong by caution, not by data.

Proposal

One agent per role

RoleModelEffortToolsWhy
Leadyour sessionyoursallIt talks to you and holds the plan; not an agent file
DeveloperSonnetmediumallCodes from a clear brief; tests and review catch misses
TesterSonnetmediumallWrites tests; a failing run proves each one
ReviewerOpushighRead, Grep, Glob, BashThe judgement gate; it reports, it never fixes
QASonnetmediumall, including the browserRuns real flows; the evidence shows the result
MarketerSonnetmediumRead, Write, Edit, Glob, Grep, webDrafts only; no shell, so it can't publish

Each agent loads its skill, so the rules stay in one place. A project's Team setup can override any role's model, for example "developer: Opus" on a hard codebase.

How the lead dispatches

Escalate on failure, not by default

1 Start at the role's default→ 2 Fails a review or test round: raise effort→ 3 Fails again: move up one tier (Sonnet → Opus)→ 4 Still stuck: blocker to you

Start the developer on Opus when

  • the item changes the data model or a public API
  • it touches auth, payments or personal data
  • it spans several modules

Always

  • Set the agent explicitly; never rely on inherit
  • Give each role a self-contained brief, not "read the whole plan"
  • Run parallel work only for independent items or read-only checks
  • The feature-level security review runs at xhigh

Safety and limits

Tools now back up the written rules

Stronger

The reviewer can't edit and the marketer can't run commands. Agents keep your permission mode; plugin agents can't change it.

Claude Code only

Codex, Gemini, Copilot and Cursor ignore agents/ and keep using the skills as today.

To prove before release

  • Effort works in plugin agents
  • A plugin skill preloads into its agent
  • The guard hook fires for agents' commands

The reviewer keeps Bash to run tests and git, so it could still write files through the shell. Its skill forbids that; the tool limit narrows the risk but doesn't remove it.

Cost

About half the per-token price for four of the five roles

Output price per million tokens

  • Today on an Opus session: every role $20
  • Today on a Fable session: every role $50
  • Proposal: developer, tester, QA and marketer $10; reviewer $20

Not measured yet

Per-token price isn't cost per finished task. If a Sonnet role needs extra rounds, the saving shrinks. The test runs report it per role, and a role that does worse goes back to Opus.

Plan

Prove the unknowns first, then build

1 Spike: check the 3 unknowns in a test session→ 2 5 agent files, plus a CI check that each sets its model and tools→ 3 Lead dispatch rules→ 4 Rerun every role's pressure tests on its new model→ 5 README, reviews, v0.3.0 release

How you'll check it

  • In Claude Code, open /agents: five my-tech-team: agents, each showing its model
  • Ask the reviewer to "just fix" a typo: it can't, and it reports the fix to the developer instead
  • Read the test results: each role passes on its new model, or stays on Opus

Decisions needed

Four answers

1. Approve this design?

One agent per role, with the model, effort and tools on the proposal slide.

2. Marketer on Sonnet or Haiku?

Recommendation: Sonnet. Haiku costs 20× less, but the marketer's privacy and claim rules need judgement, and the volume is small. Others put it on Haiku.

3. Add a cheap "scout" helper?

Haiku, read-only, for questions like "where is X?". It isn't a role and you never brief it. Recommendation: yes, because Explore now uses your session model.

4. Reviewer on Opus or Fable?

Recommendation: Opus at high effort. Fable costs 2.5× more; Team setup can raise it for a project.
