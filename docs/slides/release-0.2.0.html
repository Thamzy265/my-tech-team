What is in it

Five skill upgrades and a safety hook

qa

Automates each check first. One screenshot per state, one video per flow. Writes your steps only for things that need you.

tester

Writes end-to-end tests (Playwright, Maestro), even before the tool is installed. Asks once to install.

developer

Gives every new control a stable, accessible name. Runs the end-to-end tests before hand-off.

lead

Your update shows "What we checked", with the evidence, and "What only you can check".

marketer

May use QA screenshots that show no personal data.

All roles + guard

Ask before risky commands. On Claude Code a hook makes it ask, even when a permission rule allows the command.

Known gaps

What v0.2.0 does not prove yet

Not run yet

  • Maestro on a real simulator or emulator (it waits until a mobile project needs it)
  • The guard on Windows (it needs a POSIX shell such as Git Bash)

By design

  • The guard is a safety net, not a guarantee: the written rules still apply
  • It runs on your machine with your permissions; the README says so

Release and rollback

How it ships

1 Open the PR (ASD-STE100), CI on Linux and macOS→ 2 Merge→ 3 Tag v0.2.0 and publish the GitHub release→ 4 Install from GitHub: 6 skills and 1 hook→ 5 project-deck switches to v0.2.0

Rollback

Revert the merge and delete the tag and release. project-deck stays on whatever version it pins.

Decisions needed

Two answers

1. Open the PR, merge and release v0.2.0?

Recommendation: yes, after the final review findings are fixed.

2. Then update the project-deck branch to v0.2.0 and hand you its 5-minute check?

Recommendation: yes. One-line pin change plus the new Team setup keys.
