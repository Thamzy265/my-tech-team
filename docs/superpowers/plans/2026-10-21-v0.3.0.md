# v0.3.0 One Agent per Role: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The plugin ships one Claude Code agent per role (plus a cheap scout), each with its own model, effort and tools, and the lead dispatches to them with an escalation ladder.

**Architecture:** Six Markdown agent files in `agents/` (Claude Code scans this folder by default; no manifest change). Each role agent preloads its role skill with `skills: [my-tech-team:<role>]`, so the rules stay in the skills. A new linter (`scripts/lint_agents.py`) enforces the model, effort and tool rules in CI. The lead skill gets a "Dispatching on Claude Code" section. Skills stay portable; other AI tools ignore `agents/`.

**Tech Stack:** Markdown + YAML frontmatter, Python 3 stdlib (`unittest`), POSIX sh, Claude Code 2.1.236 CLI (`claude plugin validate`, `claude -p --plugin-dir`).

**Spec:** `docs/superpowers/specs/2026-10-20-v0.3.0-role-agents-design.md`. **Spike:** `docs/testing/results/v0.3.0-spike.md`.

**Branch:** `docs/v0.3.0-role-agents` (already holds the research, deck, spec and spike). Commit after each task. Commits are Conventional Commits and end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

**Host safety for every task:** work only inside the repo and the session scratchpad. No installs, no pushes, no `git reset --hard`, no deleting outside the scratchpad.

```python
#!/usr/bin/env python3
"""Lint my-tech-team plugin agents (agents/*.md): models, effort, skills and tool limits."""
import sys
from pathlib import Path

ROLES = ["developer", "tester", "reviewer", "qa", "marketer"]
EXPECTED = set(ROLES) | {"scout"}
MODELS = {"haiku", "sonnet", "opus", "fable"}  # never inherit: it runs the PM's session model
EFFORTS = {"low", "medium", "high", "xhigh", "max"}
# Claude Code ignores these in plugin agents, so setting them would give false comfort.
PLUGIN_IGNORED = {"hooks", "mcpServers", "permissionMode"}
WRITE_TOOLS = ["Edit", "Write", "NotebookEdit"]
NO_WRITE = {"reviewer", "scout"}
NO_SHELL = {"marketer"}
NEEDS_SKILL_TOOL = {"reviewer", "marketer"}


def parse(text):
    """Return frontmatter as {key: str or list}. Only the YAML subset the agents use."""
    lines = text.splitlines()
    if not lines or lines[0].strip() != "---":
        raise ValueError("must start with '---' frontmatter")
    try:
        end = lines.index("---", 1)
    except ValueError:
        raise ValueError("frontmatter is not closed with '---'")
    meta, key = {}, None
    for line in lines[1:end]:
        if not line.strip():
            continue
        if line.startswith((" ", "\t")):
            item = line.strip()
            if key and item.startswith("- "):
                if not isinstance(meta.get(key), list):
                    meta[key] = []
                meta[key].append(item[2:].strip().strip('"').strip("'"))
            continue
        key, _, value = line.partition(":")
        key = key.strip()
        meta[key] = value.strip().strip('"').strip("'")
    return meta


def as_list(value):
    if isinstance(value, list):
        return value
    return [v.strip() for v in (value or "").split(",") if v.strip()]


def lint_agent(path):
    path = Path(path)
    name = path.stem
    try:
        meta = parse(path.read_text())
    except ValueError as exc:
        return [f"{path}: {exc}"]
    errors = []
    if meta.get("name") != name:
        errors.append(f"{path}: name '{meta.get('name')}' does not match file '{name}'")
    if not meta.get("description"):
        errors.append(f"{path}: description is required")
    if meta.get("model") not in MODELS:
        errors.append(f"{path}: model must be one of {sorted(MODELS)} (got '{meta.get('model')}')")
    if meta.get("effort") not in EFFORTS:
        errors.append(f"{path}: effort must be one of {sorted(EFFORTS)} (got '{meta.get('effort')}')")
    for key in sorted(PLUGIN_IGNORED & set(meta)):
        errors.append(f"{path}: '{key}' is ignored in plugin agents; remove it")
    if name in ROLES and f"my-tech-team:{name}" not in as_list(meta.get("skills")):
        errors.append(f"{path}: skills must include 'my-tech-team:{name}'")
    tools = as_list(meta.get("tools")) if "tools" in meta else None
    if name in NO_WRITE | NO_SHELL | NEEDS_SKILL_TOOL and tools is None:
        errors.append(f"{path}: {name} must set tools")
    if tools is not None:
        if name in NO_WRITE:
            for t in WRITE_TOOLS:
                if t in tools:
                    errors.append(f"{path}: {name} must not have {t}")
        if name in NO_SHELL and "Bash" in tools:
            errors.append(f"{path}: {name} must not have Bash")
        if name in NEEDS_SKILL_TOOL and "Skill" not in tools:
            errors.append(f"{path}: {name} must have Skill")
    return errors


def lint_dir(root):
    root = Path(root)
    files = {p.stem: p for p in sorted(root.glob("*.md"))}
    errors = []
    for name in sorted(EXPECTED - set(files)):
        errors.append(f"{root}: missing agent '{name}'")
    for name in sorted(set(files) - EXPECTED):
        errors.append(f"{root}: unexpected agent '{name}'")
    for name in sorted(set(files) & EXPECTED):
        errors.extend(lint_agent(files[name]))
    return errors


def main(argv):
    root = Path(argv[0]) if argv else Path(__file__).resolve().parent.parent / "agents"
    errors = lint_dir(root)
    for e in errors:
        print(e)
    print(f"lint_agents: {len(list(root.glob('*.md')))} agents, {len(errors)} errors")
    return 1 if errors else 0


if __name__ == "__main__":
    sys.exit(main(sys.argv[1:]))
```

### Dispatching on Claude Code

The plugin ships one agent per role. Dispatch each role to its agent by name. Never use a generic agent for a role: it runs on the PM's session model with every tool.

| Role | Agent | Model · effort | Tools |
|---|---|---|---|
| Developer | `my-tech-team:developer` | Sonnet · medium | all |
| Tester | `my-tech-team:tester` | Sonnet · medium | all |
| Reviewer | `my-tech-team:reviewer` | Opus · high | read, shell and skills; no edits |
| QA | `my-tech-team:qa` | Sonnet · medium | all, including the browser |
| Marketer | `my-tech-team:marketer` | Sonnet · medium | files and web; no shell |
| Lookups | `my-tech-team:scout` | Haiku · low | read and search only |

- **Lookups.** Send "where is X", "what calls Y" or "which files touch Z" to the scout instead of reading many files yourself. The scout is not a role: it has no gate and doesn't appear in PM updates.
- **Briefs are self-contained:** the task, the interfaces, the decisions so far and the exact files to read. Never "read the whole plan".
- **Escalation.** Start at the agent's defaults. When the same item fails a review, test or QA round, dispatch the role again one effort level higher. When it fails again, dispatch it on `opus`. When it is still stuck, raise a blocker to the PM. Write each step in the status log.
- **Start the developer on `opus`** when the item changes the data model or a public API, touches auth, payments or personal data, or spans several modules. Say why in the brief.
- **Feature-level security review:** dispatch the reviewer at `xhigh` effort.
- **Team setup override.** If Team setup has an "Agent models" line (for example `developer: opus` or `reviewer: fable, xhigh`), use that model and effort every time you dispatch that role.
- **Parallel work** only for independent items or read-only checks. Steps for one item stay in order.
- **No agents** (the skills were copied without the plugin): dispatch a subagent per role, tell it to use its skill, and set its model and effort to match the table.
```

## Models and agents (Claude Code)

On Claude Code, the plugin has one agent for each role. Each agent has a model, an effort level and a set of tools that agree with its work:

| Role | Model | Effort | Tools |
|---|---|---|---|
| Lead | your session model | your setting | all |
| Developer, tester, QA | Sonnet | medium | all |
| Reviewer | Opus | high | read, shell and skills. It cannot edit files |
| Marketer | Sonnet | medium | files and web. It has no shell |
| Scout (lookups for the lead) | Haiku | low | read and search |

The lead sends each role to its agent. When a role fails a review, test or QA round, the lead increases the effort. When the role fails again, the lead uses Opus. When the role is still not successful, the lead tells you.

To change the model for a role in your project, add an "Agent models" line to Team setup. Example: `Agent models: developer: opus; reviewer: fable, xhigh`.

The agents use the model names `sonnet`, `opus` and `haiku`. Claude Code changes these names to the newest models that your version knows. If your organisation limits models with `availableModels`, that limit applies to the agents too.

Codex, Gemini CLI, GitHub Copilot and Cursor do not use the agents. They use the skills as before.
```
