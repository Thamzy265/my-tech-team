# Pressure test results: v0.3.0

Date: 21–22 Oct 2026. Claude Code 2.1.236. Branch `docs/v0.3.0-role-agents`. Scenarios: [../pressure-tests.md](../pressure-tests.md). Spike: [v0.3.0-spike.md](v0.3.0-spike.md).

Method:
- **Behaviour runs** (L6, D1, T1, R1, Q1, M1): fresh `general-purpose` subagents, each in its own fresh copy of `tests/sample-project` in the session scratchpad, with the fixture built by the controller. Each was told to use the branch skill. Model and effort were set to the role's new agent settings: Sonnet at `medium` for the developer, tester, QA and marketer; Opus at `high` for the reviewer; Opus for the lead (the PM's session).
- **Real agents** (A1–A4): `claude -p --plugin-dir <repo> --model sonnet --output-format stream-json --verbose` in fresh copies. The main session only dispatched. Models are read from the agent transcripts.

REFACTOR from the GREEN run: the skill didn't say what effort to use on the `opus` step, or which role escalates when a test fails. The run chose sensibly (kept high; escalated the developer, not the tester). The lead skill now says both: "dispatch it on `opus`, keeping the raised effort. Escalate the role whose work failed (a failing test escalates the developer, not the tester)."

## Limitations found

- **Headless runs can't read skill references from a `--plugin-dir` outside the project.** In A2 the reviewer couldn't read `references/security.md`, run the check command or create the temporary git ref for `security-review`, because `-p` can't show permission prompts. A normal Skill-tool load behaves the same (checked: same "requested permissions to read" denial), so v0.3.0 didn't cause it. In an interactive session Claude Code asks the PM instead.
- **The marketer can't list or search folders** (no shell, and no Grep or Glob in 2.1.236). The lead's brief must name every file; the agent asks for paths when it needs them (A3).
- **The reviewer has no Agent tool**, so the `security-review` and `code-review` skills run without their own subagents inside it. It did its review by hand in A2 and R1.
- The behaviour runs used general-purpose subagents with the agents' model and effort, not the plugin agents themselves; A1–A4 cover the agents' tool limits and models.
